# New Project Wizard verification matrix

Automated coverage lives in:

- `ArmeriaWizardTemplateCoverageTest` — every wizard library id has a matching `hasLibrary(...)` block in all three build templates.
- `ArmeriaWizardTemplateRenderingTest` — renders Velocity templates for the representative wizard combinations below.

## Representative scenarios

| # | Build | Language | Libraries | Expected in generated build file |
|---|-------|----------|-----------|----------------------------------|
| 1 | Gradle (Kotlin DSL) | Kotlin | `armeria-grpc`, JUnit 5 | `kotlin("jvm")`, `armeria-grpc`, `armeria-kotlin`, `armeria-junit5`, `useJUnitJupiter()` |
| 2 | Gradle (Groovy) | Scala | `armeria-scala_2.13` | `id 'scala'`, `armeria-scala_2.13`, `scala-library:2.13.8` |
| 3 | Maven | Kotlin | `armeria-tomcat8` | `<artifactId>armeria-tomcat8</artifactId>`, `kotlin-maven-plugin` |
| 4 | Gradle (Kotlin DSL) | Kotlin | `armeria-spring-boot3-starter` | `armeria-spring-boot3-starter`, `application.yml`, `ArmeriaConfiguration` |
| 5 | Gradle (Kotlin DSL) | Java | `armeria-grpc` | `armeria-grpc`, `src/main/proto/hello.proto`, `HelloServiceImpl` |
| 6 | Gradle (Groovy) | Scala | core Armeria | `Main.scala` and `BlogService.scala` (compilable-looking sample; JUnit test is not generated) |

## Files always generated by `ArmeriaModuleBuilder.getAssets`

| Build type | Files |
|------------|-------|
| Gradle (Kotlin DSL) | `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties` |
| Gradle (Groovy) | `build.gradle`, `settings.gradle`, `gradle.properties` |
| Maven | `pom.xml` |
| All (Java/Kotlin) | `src/main/{java\|kotlin}/<package>/Main.{java\|kt}`, `src/main/{java\|kotlin}/<package>/BlogService.{java\|kt}`, `src/main/resources/logback.xml`, `src/test/{java\|kotlin}/<package>/MainTest.{java\|kt}` when JUnit 5 is selected, package-scoped source directories |
| Scala | `src/main/scala/<package>/Main.scala`, `src/main/scala/<package>/BlogService.scala`, `src/main/resources/logback.xml`, empty `src/main/scala/<package>/` / `src/test/scala/<package>/` directories (no JUnit sample) |
| Spring Boot library selected | `src/main/resources/application.yml` (`spring.main.web-application-type: none`, `armeria.ports`) and `<package>/ArmeriaConfiguration` (`ArmeriaServerConfigurator` bean) instead of `Server.builder()` in `Main` |
| gRPC library selected | `src/main/proto/hello.proto` and `<package>/HelloServiceImpl` wired from `Main` or `ArmeriaConfiguration`. Build files add the protobuf Gradle/Maven plugin so generated stubs compile. |

| Kotlin language selected | `BlogService` route methods are `suspend`; build files always include `armeria-kotlin` (library checkbox optional) |
| All languages | `Main` / `ArmeriaConfiguration` mounts `DocService` under `/docs` via `serviceUnder("/docs", ...)` |

Not generated by this plugin: Gradle Wrapper, Java toolchain pins.

## Optional manual QA (`runIde`)

1. `./gradlew :plugin:runIde`
2. **New Project** → Armeria → run each row in the table above.
3. Confirm the generated tree matches the table and `./gradlew build` (or `mvn -q test-compile`) succeeds.
